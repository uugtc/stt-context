# STT Context

会議の背景を知る、Mac向けの文字起こし・議事録アプリ。

資料、専門用語と読み方、自由文を事前に登録し、外部の音声認識APIに背景情報を渡します。例えば「えし」を「絵師」ではなく「壊死」と認識しやすくすることを目指しています。**認識精度の改善幅は未評価です。プロンプトは正解を保証しません。**

## 初版の機能

- Macのマイク＋システム音声、またはマイクのみの録音。独立トラックとミックスを保存。
- 音声ファイル取り込み（MP3/M4A/WAV/WebM/MP4/AAC/FLAC/OGG）。
- テーマごとの資料・用語・背景説明と、会議固有の背景情報。
- PDF/TXT/Markdownの読み取り、APIによる背景整理・用語抽出。
- 話者識別→背景情報付き音声認識→根拠の発言にリンクする要約。
- 発言/話者の修正、区間再生、部分再認識の候補比較、用語登録。
- Markdown/TXT書き出し、ローカルSQLite保存、途中処理の再開。

## 開発環境

- macOS 15以降（開発時の実機はmacOS 26.3）
- Node.js 24以降、npm
- FFmpeg（フル版Xcodeは不要。環境によりCommand Line Toolsは必要）
- AI処理には自分のOpenAI APIキー

```bash
npm ci
# Electronのバイナリが未取得の場合
node node_modules/electron/install.js --no
npm run dev
```

FFmpegが未導入の場合は `brew install ffmpeg`。通常のHomebrewの場所から自動検出し、別の場所なら設定画面で実行ファイルを指定します。

1. 設定画面にAPIキーを登録。キーなしでもテーマ管理と録音は使えます。
2. 必要ならテーマを作り、用語・資料を追加。
3. 新しい会議を作り、録音または音声を取り込み。
4. マイク／画面・システムオーディオ録音のmacOS権限を許可。
5. 停止後に自動処理。キー未設定なら登録後に「文字起こし・要約を作成」。

Electronの開発版ではTerminalやエディタ側に録音権限が必要になる場合があります。システム設定で許可し、アプリを再起動してください。録音中のメーターで実際に音が入っていることを確認します。システム音声はMac全体で、会議アプリだけに限定されません。映像は保存しません。

## 起動用アプリを作る

```bash
npm run package
```

`release/mac-arm64/STT Context.app`（Apple Siliconの場合）を開きます。証明書による署名・公証・App Store配布は未設定です。GitHubでソースを公開することと、第三者へ署名済みアプリを配布することは別の作業です。

## データと外部送信

- 保存先：ElectronのuserData（通常 `~/Library/Application Support/STT Context`）。
- DB：`context.sqlite`。音声：`meetings/<id>/`、資料コピー：`documents/`。
- APIキー：`api-key.enc`。Electron safeStorageによる暗号化（macOSキーチェーンに依存）。画面には読み戻しません。
- 音声認識には音声と背景情報、資料整理には抽出文章、要約には文字起こしをOpenAIへ送信します。完全オフラインではありません。
- 会議削除は該当会議の音声・変換ファイルも削除します。資料コピーは共有され得るため、現在は参照を外してもローカルに残ります。
- 会議作成時のテーマ情報と、最初の処理に用いた背景を保存。後のテーマ編集で過去の会議が書き換わることはありません。
- 話者識別時の下書きは `originalText`、背景情報付きの認識結果は `recognizedText`、編集済み本文は `text`、再認識は `candidate` として区別。編集前の本文は `revisions` に保存し画面から確認できます。
- 再開時は音声ファイルのハッシュを照合し、最初に選んだ認識モデルを保持します。別の音声やモデルの結果が無意識に混在することを防ぎます。

## 構成

```text
src/main/       SQLite / ファイル / FFmpeg / API / ジョブ / IPC
src/preload/    型付きで限定したElectronブリッジ
src/renderer/   React UI / MediaRecorder / 音量メーター
src/shared/     データ型 / 入力検証 / 背景情報 / 発言区間
tests/         文脈・永続化・メディア・API境界・ジョブのテスト
scripts/       Electron結合テスト
docs/          承認済み設計と実装計画
```

UIはNode.jsへ直接アクセスできず、APIキーとファイル操作はmain側に限定。型付きIPCに加え実行時にも入力を検証します。外部ページへの遷移は許可しません。音声配信は会議IDを検証する専用プロトコルです。

初期モデル：話者識別 `gpt-4o-transcribe-diarize`、音声認識 `gpt-4o-transcribe`、整理/要約 `gpt-5.6-luna`（推論なし）。設定で変更できます。各モデルがアカウントで使用可能かは実API接続時に確認してください。

## テスト

```bash
npm test
npm run typecheck
npm run build
npm run smoke
```

`smoke` は別の一時プロファイルとChromiumの人工音声を使います。ユーザーの会議やマイクを録音せず、実APIにも接続しません。テーマ/用語/会議作成・会議名変更・人工音声録音・背景情報の自動保存・音声読込・保存・録音中の画面再読込からの復旧・rendererの分離を確認し、`test-results/` に画面を保存します。実際のシステム音声取得やOSの録音許可はこのテストでは検証できません。

配布用ビルドも `STT_PACKAGED_APP="$(pwd)/release/mac-arm64/STT Context.app/Contents/MacOS/STT Context" npm run smoke` で同じ検証が可能です。

## 現在の制約・未検証事項

- 実マイクとシステム音声の同時録音、機器切断、スピーカーからの回り込みは実機での追加確認が必要です。ヘッドホン使用を推奨。
- 実APIの料金・処理時間・専門用語精度は未測定。ローカルテストとAPI通信形式のテストは、認識精度の証明ではありません。
- 約15分単位で処理します。分割をまたぐ話者IDは自動統合せず、別IDで表示します。同一人物と分かれば名前を統一してください。
- 発言時刻は話者識別モデルの区間です。単語ごとの厳密なタイミングではありません。同時発言の完全な分離はできません。
- 未割当区間の検出には音量に基づく簡易判定を使用。小声の取りこぼし／雑音の過検出はあり得ます。
- 認識用文脈は上限内に収め、手動用語を優先。省略が生じた場合は使用文脈の詳細に表示。
- 画像PDF/OCR、Word/PowerPoint、フォルダ同期、リアルタイム表示、チーム共有は対象外。
- 録音は1秒単位で追記します。異常終了直前のバッファやファイル末尾が失われる可能性があります。

## 精度評価の手順

1. 公開してよい短い音声と正解文を用意する（専門用語を含むものと含まないもの）。
2. 同じ音声を別の会議に取り込み、背景なし／単語＋読み／資料＋背景の3条件で処理。
3. 用語の正答率、言っていない用語の挿入、否定/数字の保持、話者の誤割り当てを比較。
4. モデル・使用文脈・音声を固定し、調整に使っていない音声でも確認。

APIキー・私的な音声・背景資料・ローカルDBはリポジトリに含めないでください。GitHub公開時はREADME、公開可能な評価用音声、評価結果、短いデモを添える想定です。ライセンスは公開時に選定します。
